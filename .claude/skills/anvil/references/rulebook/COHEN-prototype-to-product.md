## 3. Mechanizable checks

`CHECK-edge-keepout`: inputs = layout geometry (trace/pad edge distance mil, component edge distance mil) → pass if min(edge_to_copper) ≥ 50 mil AND min(edge_to_component) ≥ 100 mil → margin = measured − limit (mil). Source COHEN-045.

`CHECK-feeder-count`: inputs = BOM (unique part numbers N_u), CM feeder capacity N_f (20–100+) → pass if N_u ≤ N_f (single pass) → margin = N_f − N_u; warn "multiple pick-and-place passes" otherwise. Source COHEN-038.

`CHECK-reel-moq-cost`: inputs = per line: unit price p, reel qty q_reel, build qty q_build, cut-tape available? → effective_unit = p × q_reel / q_build if full reel must be bought, else p → pass if Σ(effective − p) × q_build ≤ tolerance; report lines where effective_unit > 2p. Source COHEN-039.

`CHECK-through-hole-count`: inputs = BOM package types → count TH parts; pass if TH parts are only those needing mechanical strength (user-accessed connectors) → margin = N_TH. Source COHEN-036.

`CHECK-block-granularity`: inputs = architecture blocks with mapped chip count → pass if every block maps to ≤ 2 chips (+battery) → flag blocks with > 2. Source COHEN-072.

`CHECK-automation-payback`: inputs = manual step time t (min), lifetime volume V, automation cost C_auto, labor rate r ($/min, default 1) → savings = t × r × V → automate if savings > C_auto → margin = savings − C_auto. Source COHEN-053.

`CHECK-cogs-estimate`: inputs = BOM cost B (per qty tier) → COGS_est = 2 × B (PCBA + simple enclosure) → compare to plan COGS; pass if plan ≥ COGS_est → margin = plan − COGS_est. Source COHEN-074.

`CHECK-enclosure-fraction`: inputs = electronics component cost E, enclosure cost X → ratio X/E; expected 0.10–0.20 for simple enclosures; flag if outside (over-designed enclosure or under-estimated). Source COHEN-071.

`CHECK-gross-margin`: inputs = retail price P, COGS, channel discount d (0.15–0.33), industry band [lo, hi] (consumer electronics 0.30–0.50) → GM_direct = (P − COGS)/P; GM_channel = (P(1−d) − COGS)/(P(1−d)) → pass if GM_channel ≥ lo → margin = GM_channel − lo; warn if GM_direct > hi (undercut risk). Source COHEN-075, -076.

`CHECK-return-rate-budget`: inputs = expected return rate r, gross margin GM → flag if r ≥ 0.01 in low-margin market (GM near band low). Source COHEN-105.

`CHECK-contingency`: inputs = base cost/time, team experience class, technology novelty → required contingency: experienced+known = 20–30 %; inexperienced or new tech = ≥ 50 % (ch12) / expect ≥ 100 % overrun (ch01) → pass if plan contingency ≥ required. Source COHEN-012, -263.

`CHECK-budget-phasing`: inputs = spend at end of detailed definition S_def, total budget T → ratio S_def/T; expected 0.25–0.33 → flag if ratio > 0.40 (definition over-spent) or plan assumes < 0.60 of budget remains for detailed development. Source COHEN-112.

`CHECK-se-pm-budget`: inputs = personnel budget, SE+PM allocation → pass if allocation ∈ [15 %, 20 %] (or ≥ 15 %). Source COHEN-263.

`CHECK-task-granularity`: inputs = task list with durations → flag tasks < 0.5 day not marked as milestone/meeting; flag tasks with no owner or no resource. Source COHEN-008, -263.

`CHECK-coin-cell-life`: inputs = capacity C (mAh), target life t (h), mode table (I_i, duty f_i), derating factor k (≤ 1, default 0.5 for cold/high-rate) → I_avg = Σ I_i f_i; life = k × C / I_avg → pass if life ≥ t → margin = life/t − 1. Anchor: CR2016 80 mAh → 10 µA/yr. Source COHEN-094, -144, -189.

`CHECK-battery-droop`: inputs = V_oc, R_int (fresh and end-of-life), I_peak, V_cutoff/V_min(system) → V_term = V_oc − I_peak × R_int → pass if V_term ≥ V_min for both R_int values → margin = V_term − V_min. Anchors: CR2032 50 Ω, AA 0.2→1 Ω. Source COHEN-190.

`CHECK-rail-current`: inputs = per rail: Σ load average, Σ load peak (start-up, motor/H-bridge, lighting), regulator I_max, regulator I_min (switchers) → pass if I_peak ≤ I_max and I_avg ≥ I_min → margin = I_max − I_peak. Source COHEN-213.

`CHECK-rail-tolerance`: inputs = per rail: nominal V, regulator accuracy (±1 % if per datasheet), measured/simulated bounce ΔV, tightest powered-part supply tolerance tol → pass if (accuracy + ΔV/V) ≤ tol. Source COHEN-213, -058.

`CHECK-decoupling-presence`: inputs = netlist: for each IC supply pin, presence of bulk cap (≥ 1 µF) and bypass cap on the same rail near the pin → pass if every supply pin has both (or datasheet-specified) → report missing. Source COHEN-214.

`CHECK-linear-loss`: inputs = per linear regulator: V_in, V_out, I_out → P_loss = (V_in − V_out) × I_out; eta = V_out/V_in → warn if eta < 0.6 or P_loss exceeds thermal budget; recommend switcher when eta < 0.6 or I high. Source COHEN-211, -212.

`CHECK-liion-charge-params`: inputs = cell capacity C, charger Ic, V_cv, I_term, pre-charge current → pass if 0.5C ≤ Ic ≤ 1.0C (prefer ≤ 0.7C), V_cv ≤ 4.2 V (4.1 V for 2× life), I_term ≈ 0.05 Ic, I_pre ≈ 0.1 Ic; compute t_charge ≈ 2–3 h expectation. Source COHEN-200, -202.

`CHECK-liion-thermal-cutoffs`: inputs = charger/BMS temperature window, thermistor present?, product environment T range → pass if charge inhibited outside 0–45 °C and operation outside −20–60 °C, and environment (e.g. parked car > 60 °C) is handled by cutoff. Source COHEN-203.

`CHECK-liion-protection`: inputs = cell type (protected/unprotected), UL listing, current limit in system → pass if protected + UL-listed cells OR documented system safety demonstration exists. Source COHEN-207.

`CHECK-usb-power-budget`: inputs = product input current I_in, connector type, source type support (SDP/CDP/DCP) → pass if I_in ≤ 1800 mA for micro-B, I_in ≤ 500 mA on SDP unless enumerated/CDP detected, DCP up to charger rating. Source COHEN-208, -209.

`CHECK-plug-discharge`: inputs = X-capacitance C_x across mains input, bleeder resistance R_b, V_peak → V(1 s) = V_peak × exp(−1/(R_b C_x)); Q = C_x × V(1 s) → pass if V(1 s) ≤ 60 V or Q ≤ 45 µC. Source COHEN-226.

`CHECK-lvd-scope`: inputs = all input/output voltages → EU Low Voltage Directive applies if any in 50–1000 V AC or 75–1500 V DC. Source COHEN-238.

`CHECK-fcc-class`: inputs = intended environment (home possible?) , intentional radiator? , module modular-certified? , antenna type/gain vs certified → required tests: unintentional radiator Class B if home use possible else Class A; intentional-radiator cert required unless modular-certified AND antenna same type and gain ≤ certified. Source COHEN-235.

`CHECK-rohs-bom`: inputs = BOM with RoHS flag per line (incl. resins, mechanical) → pass if all lines = yes → list missing. Source COHEN-239.

`CHECK-prop65-materials`: inputs = material/chemical list vs Prop 65 list → pass if no matches, else label required. Source COHEN-229.

`CHECK-requirement-record`: inputs = requirements table → each row must have #, statement, criticality (Mandatory/Preferred/Optional or 1–10), rationale, test method, owner; flag rows with unqualified "or", "safe", "user-friendly", "small" without number/percentile. Source COHEN-087, -251, -253, -257.

`CHECK-lurking-coverage`: inputs = requirements table tagged by category → pass if each of the 26 lurking categories (COHEN-255) has ≥ 1 requirement or an explicit "N/A with rationale". Source COHEN-255.

`CHECK-traceability`: inputs = requirements list, test procedures, mapping → coverage = |req with ≥ 1 test| / |req| → pass at 100 % (mandatory in regulated); also flag tests changed since last review whose linked requirements lack re-review. Source COHEN-148, -260.

`CHECK-test-polarity`: inputs = per use case: N_pos, N_neg test cases → pass if N_neg ≥ 1 and N_neg ≥ N_pos for UI/safety use cases. Source COHEN-146.

`CHECK-procedure-length`: inputs = estimated operator time per procedure → flag > 4 h ("no more than a few hours"). Source COHEN-142.

`CHECK-verification-effort`: inputs = feature count N (baseline N0, effort E0) → E ≈ E0 × (N/N0)^2 → report growth; use as an argument in feature-cut decisions. Source COHEN-150.

`CHECK-test-access`: inputs = netlist, test-point/via list, package types → nets_with_probe_access/nets_total; flag BGA/hidden joints needing x-ray or JTAG; pass target 100 % or documented functional coverage for the rest. Source COHEN-048, -041, -154.

`CHECK-design-transfer-package`: inputs = release folder → require schematics, Gerbers (+ pick-and-place positions), mechanical CAD (STL/SLDPRT/IGES/STEP), BOM, assembly drawings, assembly instructions (if non-trivial), test fixtures, software binaries, volume forecast → pass if all 9 present. Source COHEN-157.

`CHECK-parts-availability`: inputs = BOM lifecycle status, required availability window (e.g. 5 years from start of manufacturing), lead times → flag NRND/EOL parts, parts with lead time > planned buffer, single-source parts; low volume: inventory ≥ 6 months or lifetime buy plan. Source COHEN-027, -056, -255.

`CHECK-mold-choice`: inputs = lifetime volume V, tolerance need → steel if V > ~100,000 or high precision; aluminum for prototypes/short runs; compute tooling amortization per unit = C_mold / V. Source COHEN-131.

`CHECK-som-vs-chipdown`: inputs = projected volume V, SOM price, estimated chip-down BOM (≈ 0.5 × SOM at high volume), NRE for chip-down → SOM if V ≲ 10,000 units; otherwise compare V × (SOM − chipdown) vs NRE. Source COHEN-169.

`CHECK-mcu-power-scaling`: inputs = f_clk, V_dd options → P_rel ∝ f × V^2; report savings; anchor ATmega328P 1.8 V/4 MHz ≈ −98 % vs 5.5 V/20 MHz. Source COHEN-216, -217.

`CHECK-storage-soc`: inputs = shipping/storage SoC and temperature plan → pass if SoC ≈ 50 % and T ≈ 0–25 °C; flag 100 % SoC + ≥ 45 °C storage. Source COHEN-204.

`CHECK-power-modes-defined`: inputs = list of power states, transitions, per-state current budget, per-chip sequencing constraints → pass if every state has budget and every transition has an owner (HW/SW) and every multi-rail chip has a sequencing note. Source COHEN-215, -222, -108.

`CHECK-power-model-vs-measured`: inputs = modeled current per mode, measured → flag modes where measured > model by a large factor (book: "much more"; suggest > 1.5×) → investigate register settings/HW. Source COHEN-108.

`CHECK-pilot-first-article`: inputs = first-article checklist (functionality, all mechanical tolerances, solder/flux residue) → pass if every item recorded on pilot units, and reliability/certification tests scheduled on production units. Source COHEN-029.

## 4. Verification procedures & plots

1. **Average-current per radio state (battery life).** Setup: µCurrent Gold (1 mV/nA range, "BATT OK" lit) in series at jumper J1; oscilloscope averaging at 1 Msps over a 10 s window. Sweep: each radio/system state (advertising 1 s, advertising 10 s, connected, sleep…). Plot: bar chart I_avg per state with pass limits (< 15 µA @ 1 s adv, < 5 µA @ 10 s adv). Then state-occupancy from use-case procedures → weighted I_avg → battery life = capacity / I_avg; plot life vs. advertising interval. Good = life ≥ requirement (7 months preferred / 1 year goal) with derated capacity. (§ch06 Table 6-1; §ch05 Table 5-1 #3.)

2. **Power model vs. measurement.** Plot modeled vs. measured current per mode; flag any mode exceeding the model materially — usual causes: unset control registers, HW design, manufacturing. (§ch05.)

3. **Unit-level supply-corner test.** For each circuit, run functional checks at the supply's guaranteed min and max voltage (and at battery cutoff voltage / simulated discharging supply via the works-like board's external-supply input). Pass = full function at both corners. (§ch06.)

4. **Li-ion charge profile plot.** x = time, y = cell voltage and charge current; expect pre-charge (≈ 0.1 Ic) below 3.0 V, CC at Ic to 4.2 V (or chosen 4.1/4.0 V), CV taper to ≈ 0.05 Ic, termination, then topping-charge restarts on voltage threshold; total 2–3 h. Also verify charge inhibit outside 0–45 °C via thermistor. (§ch09 Fig 9-9.)

5. **Battery discharge curves.** Datasheet or measured V vs. delivered mAh at the product's actual load profile (pulsed), at room temperature and at the cold extreme; derive usable capacity to the shutdown voltage; expect ≥ 50 % loss at high rate/≤ 0 °C for some chemistries. (§ch09.)

6. **Rail integrity.** Scope each rail at the IC pins during worst-case switching (start-up inrush, motor/H-bridge, LED flash, radio TX): measure sag/spikes vs. part tolerance; verify bulk/bypass placement; for switchers compare with datasheet reference layout. (§ch09.)

7. **Power-sequencing capture.** Multi-channel scope/logic capture of all rails and key enables at power-up and power-down; verify order, inter-rail delays and ramp rates against each chip's datasheet; verify no inputs driven before supply where prohibited. (§ch09.)

8. **USB source compatibility matrix.** Test against a range of wall warts (DCP), older computer ports (SDP), CDP hubs, car adapters: record enumeration, current drawn, charging state, switchover behaviour on cable pull; pass = correct behaviour with all, current ≤ 1800 mA on micro-B. (§ch09, §ch11.)

9. **EMC pre-compliance.** Build the FCC test application that sequences hardware states one at a time; pre-scan radiated emissions in each state (and with worst-case cables) against Class B/A limits before booking the lab; for modular radios verify antenna type/gain vs. the module certification. (§ch01, §ch10.)

10. **Water-ingress screen.** Water-finder paper inside sealed prototype; washing machine / dishwasher cycles; then formal IP67 (1 m) verification and the preferred 9 ft test to 95 % confidence. (§ch05 Fig 5-18; §ch05 Table 5-1 #5/#6.)

11. **Mechanism life test.** Multiple prototypes through many thousands of cycles; robotic actuation (e.g. 10,000 button presses); plot failures/degradation vs. cycles; statistical treatment for reliability claims. (§ch05, §ch06.)

12. **Step-accuracy validation.** Representative range of users walk a course; compare device count to manual count; pass = within 5 % (tight form: for 90 % of population, 95 % confidence). (§ch05 Table 5-1 #2.)

13. **Manufacturing functional test log analysis.** Store per-unit results (serial, date/time, operator, per-step values) in a database; trend plots of advertising current, paired current, accelerometer readings across lots to detect process drift (e.g. flux residue → current failures). (§ch06.)

14. **Burn-in / bathtub.** Failure rate vs. time (Fig 6-23 graph): high infant mortality → flat → wear-out. Sample-based burn-in per lot for process monitoring. (§ch06.)

15. **Reflow profile.** Temperature vs. time (Fig 3-9 graph): controlled ramp (no thermal shock), soak (flux activation and board-wide equalization), reflow peak, controlled cool; verify per paste datasheet with a profiler. (§ch03.)

16. **3D fit check.** Import ECAD 3D PCBA (vendor-verified component models, incl. alternates) into MCAD; check clearances to metal, cable lengths/routes, connector access; 3D-print and trial-assemble. (§ch06.)

## 5. Pitfalls, failure modes, review checklist

- Serious testing (usability, integration, system) deferred to the end of development (Sin #1). §ch01
- Requirements not comprehensive; subjective attributes without measurable criteria (Sin #4). §ch01
- No detailed project plan with owners, person-hours, costs, dependencies (Sins #5, #6). §ch01
- Imposed (regulatory) requirements discovered after design (Sin #7); customs holding shipments over CE labeling. §ch01
- Feature creep after requirements lock (Sin #8); test effort explodes with feature count. §ch01
- Contingency omitted because management balks — keep a written risk list to justify it. §ch01
- Developing technology when integrating existing technology would do (Sin #11). §ch01
- FCC test application forgotten until the lab appointment. §ch01
- Prototype parts not production-viable (LCD unavailable at first production order). §ch02
- Long-lead parts ordered only at end of development → weeks/months idle. §ch02
- Reliability/certification tests run on lab-built units instead of production units (reflow differences). §ch02
- Designs that are unbuildable or need excessive hand assembly; cables that do not fully seat; board features that trap contaminants. §ch03
- More unique parts than pick-and-place feeders → multiple passes. §ch03
- Full-reel MOQ inflating part cost for small builds. §ch03
- Through-hole parts left in an SMT design (hand soldering cost). §ch03
- Trace/pad within 50 mil or component within 100 mil of a depanel edge. §ch03
- Routed panels flexing during assembly; hand-snapping scored panels. §ch03
- BGA on the board but CM has no x-ray. §ch03
- No-clean flux left on sensitive/high-speed boards. §ch03
- Nets without probe access; functional-test-only missing out-of-tolerance rails (2.7 V ±5 % at 2.5 V). §ch03
- Connectors placed where fingers/tools cannot reach in assembly (unreliable mating). §ch03, §ch06
- Uncontrolled ECOs to the factory (capacitor swap breaking ICT). §ch03, §ch12
- Counterfeit components and batteries. §ch03, §ch09
- Deciding on market/price by asking friends ("probably will buy" = won't). §ch04
- Unobtanium in the concept (physics, volume-gated parts, prohibitive cost). §ch04
- Architecture block needing more than 1–2 chips. §ch04
- COGS estimate omitting assembly (use ≈ 2 × BOM) or mold NRE mixed into COGS. §ch04
- Gross margin outside industry band; channel discount (15–33 %) not modeled. §ch04
- User stories that bake in design decisions ("by a popup box"). §ch05
- Mandatory criticality assigned to non-showstoppers. §ch05
- Mechanisms started late; molded-part variance (0.004 in) breaking a mechanism. §ch05
- Motor drive over long cables (RF noise) instead of local driver boards. §ch05
- Cables unfastened inside the enclosure; non-locking connectors under vibration. §ch05
- Third-party software adopted without license and life-cycle support review (GPL disclosure). §ch05, §ch08, §ch11
- Risk register entries without a stated reason the risk is tolerable. §ch05
- Building the Linux driver before proving the RF chipset (wasted effort). §ch05
- Measured power far above model and not investigated. §ch05
- Vendor quotes requested as "how much for x" instead of collaborative review (missed ENIG-for-BGA, glass-filled plastic advice). §ch05
- Hardware built without software involvement; PCBAs spun before breadboard bring-up. §ch06
- Only the "risky" circuits breadboarded. §ch06
- High-speed/sensitive analog on a breadboard (invalid results). §ch06
- Works-like board without current-sense provisions, header breakouts, spare GPIO, robust debug connector. §ch06
- Layout started before agreeing stackup/features/panel with the fabricator and assembler. §ch06
- Software integrated and formally tested only at the end. §ch06
- No version control / TDD / CI. §ch06
- Molded part without draft; undercuts requiring side actions; thick ribs, abrupt wall changes. §ch06
- Mold cut "thick" first (cannot add material back). §ch06
- Screws where snap clips/heat stakes would be goof-proof; multiple screw sizes. §ch06
- Prototype technology mismatched to purpose (FDM part used to judge snap feel or regulatory tests). §ch06
- First integration: parts too tight/loose, cables short, PCB touching metal, components taller than models (bad 3D models, alternate parts). §ch06
- Test procedures without explicit pass/fail; procedures longer than a few hours; no negative cases. §ch06
- Requirement without a test (traceability gap); test changed without re-reviewing linked requirements. §ch06, §ch11
- Manufacturing test needing engineers, long runtimes, Internet on the factory floor that does not exist. §ch06
- MAC address / serial / calibration / gauge-constant programming not planned. §ch06, §ch09
- Design-transfer package incomplete (9 items). §ch06
- Application-class SoC chosen with sparse small-customer support and wrong manuals. §ch07
- Consumer motherboard with months-long availability designed in. §ch07
- FPGA used where a CPU suffices (cost, power, config loader). §ch07
- OS/processor chosen without a good BSP. §ch08
- Embedded Linux adopted without a kernel freeze/upgrade and backport policy; custom drivers needing person-weeks per kernel. §ch08
- Android stripped down for a non-phone product. §ch08
- Splash screen lost between U-Boot and kernel (CONFIG_FB_PRE_INIT_FB). §ch08
- Heavyweight OS not locked down; used where determinism matters. §ch08
- RTOS license scope (processor change) undefined in the agreement. §ch08
- Battery selected from label capacity, not datasheet curves; coin cell asked for > few mA continuous. §ch09
- 9 V battery in a product; NiMH C/D "fat-jacket" cells; NiCd in EU products. §ch09
- Blind substitution of Li-ion chemistries; unprotected/non-UL cells; home-grown charger. §ch09
- Charging at > 1 C, to 4.2 V, at > 45 °C when longevity matters; storage at 100 % SoC and 60 °C. §ch09
- SoC from voltage alone; gauge constants not programmed; battery replacement without gauge re-learn. §ch09
- Parallel cells connected at different voltages; series cells unbalanced. §ch09
- USB micro-B drawing > 1.8 A; USB source type not detected; not tested against many chargers. §ch09
- Linear regulator with large drop in the charge path or high-current rail (heat). §ch09
- Switcher layout/BOM deviating from datasheet. §ch09
- Rail current budget ignoring start-up/switching peaks; switcher below minimum load; missing bulk/bypass caps. §ch09
- Power sequencing violations; inputs driven on unpowered chips; OS drivers for depowered peripherals. §ch09
- Power path (deep-discharge boot loop, USB↔battery switchover, temperature cutoff, power button) built from discrete parts. §ch09
- PMIC charger too small for the battery. §ch09
- Regulations identified late; small manufacturer assuming exemption. §ch10
- Health claims turning a gadget into a medical device. §ch10
- Children's-product classification decided without documentation. §ch10
- Certification lab expected to identify regulations or suggest fixes; failing at the lab instead of pre-testing (hourly billing). §ch10
- Modular radio with a different/higher-gain antenna than certified. §ch10
- Class A tested when home use is plausible (needs Class B). §ch10
- Wrong edition of a standard purchased/used. §ch10
- RoHS not checked per BOM line; WEEE scheme/labeling and Battery Directive removability missed. §ch10
- Lithium battery shipping (IATA, carriers) not a requirement. §ch10, §ch05
- QMS set up after development is deep. §ch10
- Requirements with unqualified "or", "safe", "fits in a pocket". §ch11
- "How" requirements constraining designers (AA batteries) without customer need. §ch11
- Internationalization (text +50 %, privacy, documentation) missed. §ch11
- Internal interface specs "perfected" instead of integrated early. §ch11
- Lurking categories (storage temperature, RTC battery, parts availability, licensing…) missing. §ch11
- Requirements written by one person and circulated. §ch11
- Plans without SE/PM time (15–20 %), without contingency, with tasks under half a day or without owners. §ch12
- Working from unreleased/local document copies; changes without CR/CO; CR→CO latency not planned. §ch12
